# YTPios

Адаптивный браузерный интерфейс в стиле мобильного видеоприложения с официальным встроенным плеером YouTube. Самостоятельный сайт; не изменяет youtube.com и не является продуктом Google.

**Требование полной интеграции сохраняется:** текущий интерфейс — прототип. См. [обязательные требования](REQUIREMENTS.md) и [список API и ручных настроек Google](docs/GOOGLE_INTEGRATION.md).

## GitHub Pages

Если Pages настроен на **Deploy from a branch → main → / (root)**, корневой `index.html` перенаправляет на `./public/`, где приложение работает без сборки. `.nojekyll` отключает обработку Jekyll. Client ID удалён из исходников. Для общего входа используйте Actions с переменной `GOOGLE_CLIENT_ID`; публикация ветки требует локальной настройки. Client Secret не используется.

В репозитории настроен `.github/workflows/pages.yml`: push в `main` запускает установку через `npm ci`, тесты, сборку и публикацию каталога `dist`. Версия Node задаётся в `.nvmrc` (22); esbuild и Playwright зафиксированы в `package-lock.json`. Chromium и его системные зависимости устанавливаются в workflow перед браузерными тестами. Приложению на Pages Node-сервер не требуется — публикуется статический HTML.

Один раз выберите **Settings → Pages → Source: GitHub Actions**. Обычный `GITHUB_TOKEN` workflow не используется для административного включения Pages. Затем запустите **Actions → Publish GitHub Pages → Run workflow**. Ожидаемый адрес — `https://wizarty.github.io/YTPios/`; успешность публикации подтверждается результатом deploy, а не самим наличием workflow.

Для официального входа настройте разрешённый origin и Test users в Google Cloud по [инструкции](docs/GOOGLE_INTEGRATION.md). Публичный Client ID задаётся переменной сборки `GOOGLE_CLIENT_ID`. Секреты и токены в сборку не передаются. Проверка входа в реальный аккаунт выполняется отдельно от автоматических тестов с подменой Google.

## Локальный запуск

Нужен Node.js 22 или новее. Для работы приложения внешние npm-зависимости не нужны.

```sh
cd /workspace/YTPios
npm start
```

Сервер слушает порт 3000 (можно задать `PORT`). Для доступа с iPhone сайт нужно разместить на доступном устройству HTTPS-хостинге. Публикация и домен в этом репозитории не настроены. Работает в обычной вкладке; установка расширения не требуется.

## Что реализовано

- Адаптивная тёмная тема, мобильная нижняя навигация и боковая панель на компьютере.
- Добавление ссылок YouTube, Shorts и трансляций с пользовательским названием; проверка допустимых доменов и идентификаторов.
- Официальный YouTube IFrame Player API, встроенные элементы управления, ошибки доступности и переход к оригиналу.
- Очередь на текущий сеанс с переходом к следующему видео после окончания, сворачиваемый плеер внутри страницы.
- Избранное, история открытия и видеотека в localStorage, локальный поиск, отправка ссылки через Web Share/буфер обмена.
- Поиск внутри сайта через YouTube Data API с пагинацией и импортом найденных видео с названиями.
- Настройки ограниченного API key и OAuth Client ID прямо в интерфейсе: «Подключить Google / API» или значок «Я».
- Вход Google через Google Identity Services, чтение подписок и плейлистов, просмотр видео канала и плейлиста.
- Отдельное разрешение на изменения: подписка/отписка, создание приватного плейлиста, добавление текущего видео, оценки и публикация комментариев. Комментарии загружаются с пагинацией.
- OAuth-токены только в памяти вкладки, обработка истечения сессии, выхода, ошибок квоты и недостаточных разрешений.

Содержимое из localStorage и ответы API выводятся как текст, не HTML. Сервер раздаёт только явно перечисленные публичные файлы и устанавливает CSP. Для локальной библиотеки и плеера ключ не нужен. Для поиска и публичных данных настройте ограниченный API key или войдите через Google; для личных данных нужен OAuth. Инструкции — в [docs/GOOGLE_INTEGRATION.md](docs/GOOGLE_INTEGRATION.md).

## Границы реализации

Это начальная версия интерфейса, **не полный аналог YouTube или Premium**. Код Data API/OAuth реализован и проверен с контролируемыми ответами; живой Google Cloud проект и HTTPS-домен ещё не подключены. Персональная рекомендательная лента и полная история аккаунта не предоставляются публичным API. Редактирование/удаление существующих плейлистов и комментариев, ответы на комментарии и полная функциональная эквивалентность приложению пока не реализованы. Названия из поиска приходят из API; при ручном добавлении ссылки название задаёт пользователь. Локальные данные не синхронизируются между устройствами и исчезают при очистке данных сайта.

Реклама и спонсорские интеграции **не блокируются**. Скачивание и офлайн-просмотр отсутствуют. Мини-плеер работает внутри страницы, это не системный PiP. Фоновое воспроизведение, системный PiP, автозапуск и доступность видео определяют Safari/iOS, YouTube и правообладатель. Режим «Версия для компьютера» на youtube.com не переносится автоматически на встроенный плеер отдельного сайта.

Обложки загружаются с `i.ytimg.com`; плеер — с `www.youtube.com`, его API может использовать `s.ytimg.com`. Данные — с `www.googleapis.com`, вход — через `accounts.google.com`, отзыв разрешения может использовать `oauth2.googleapis.com`. Прямые запросы к Google выполняет браузер посетителя. Встроенный плеер может обращаться к дополнительным доменам Google для воспроизведения. Сервер не проксирует видеопоток и не получает пароли Google. Ограниченный публичный ключ и Client ID сохраняются локально; OAuth-токены не сохраняются. После перезагрузки страницы для личных данных нужен повторный вход.

## Проверки

```sh
npm ci
npm run build
npm test
npm run test:browser
npm run test:integration
```

Браузерные проверки используют Playwright и установленный Chromium (`/usr/bin/chromium`; другой путь задаётся через `CHROMIUM_PATH`). Они проверяют интерфейс на ширинах 390 и 1440 px, сохранение данных, очередь, OAuth, Data API, разделение разрешений на чтение/запись и обработку ошибок. Google Identity Services, YouTube API и обложки в этих проверках подменены контролируемыми ответами: тесты не подтверждают вход в реальный аккаунт, реальное воспроизведение YouTube, Safari, PiP или фоновую работу. Снимки интерфейса сохраняются в игнорируемый каталог `test-results`.

Перед публикацией нужна ручная проверка на iPhone по HTTPS: открытие доступного для встраивания видео, воспроизведение со звуком после нажатия, поворот экрана, полноэкранный режим, восстановление после блокировки экрана и поведение PiP. Не считать эти возможности проверенными по результатам Chromium.

## Самодостаточный файл для предпросмотра и статического хостинга

`npm run build` создаёт `dist/index.html` со встроенными CSS, JavaScript и локальными SVG-иконками. Этот файл не требует отдельных `styles.css`, `app.js` и `icon.svg`, поэтому интерфейс не теряет оформление при размещении в подкаталоге. Исходная страница также использует относительные пути.

Для работы плеера файл нужно обслуживать через HTTP(S), в эксплуатации — HTTPS. При открытии как `file://` или внутри просмотрщика вложений возможны ограничения JavaScript, хранения и плеера. Внешние обложки и YouTube по-прежнему требуют сети. Встраивание файла в стороннюю оболочку с собственной CSP может блокировать скрипты; в этом случае открыть опубликованный сайт напрямую. Политика штатного Node-сервера предназначена для исходной версии с отдельными ресурсами; этот сервер не раздаёт `dist`.
