# Интеграция YouTube и Google

## Что должен настроить владелец

### Готовые значения для GitHub Pages

Для адреса `https://wizarty.github.io/YTPios/`:

- Включите **YouTube Data API v3** в Google Cloud.
- В Google Auth Platform настройте приложение для внешних пользователей (**External**), а в режиме **Testing** добавьте свой Google-аккаунт в Test users.
- Создайте OAuth Client типа **Web application**.
- **Authorized JavaScript origins:** `https://wizarty.github.io` — без `/YTPios/` и завершающего слеша.
- **Authorized redirect URIs:** для реализованного popup token flow оставьте пустым. Обработчика `/callback` на GitHub Pages нет.
- В Data Access добавьте `https://www.googleapis.com/auth/youtube.readonly`; для кнопки изменения аккаунта также `https://www.googleapis.com/auth/youtube.force-ssl`. Для широкой публикации Google может потребовать проверку приложения.
- Откройте GitHub → репозиторий → **Settings → Secrets and variables → Actions → Variables → New repository variable**. Имя: `GOOGLE_CLIENT_ID`. Значение: созданный публичный Client ID, оканчивающийся на `.apps.googleusercontent.com`.
- Запустите **Actions → Publish GitHub Pages → Run workflow**. Сборка подставит публичный Client ID для всех посетителей. Его не нужно будет вводить на каждом устройстве; пользователю останется выполнить вход и дать согласие Google.
- Проверяйте опубликованный HTTPS-сайт напрямую в Safari, а не в просмотрщике вложений. Нажмите **«Я» → «Войти через Google»** и разрешите всплывающее окно, если Safari его блокирует.

### Как выглядит вход для посетителя

Кнопка **«Войти через Google»** или **«Я»** открывает панель **«Ваш YouTube»**, а затем официальное окно Google. После согласия панель получает каналы аккаунта через `channels.list(mine=true)` и показывает ссылки на них, переходы к своим подпискам и плейлистам. Кнопка **«Сменить аккаунт»** очищает прежнюю сессию оболочки и вызывает выбор аккаунта Google; при отмене выбора оболочка остаётся без авторизации. Поздние ответы для старого аккаунта не должны восстанавливать его профиль.

**«Выйти из оболочки»** удаляет локальную сессию и данные профиля из интерфейса, не выполняя выход на youtube.com. Полный отзыв разрешения доступен через **«Настройки подключения → Отключить Google»** до локального выхода или через настройки аккаунта Google. Канал подтверждает принадлежность данных API выбранному аккаунту; это не перенос cookies или полного интерфейса youtube.com. Авторизация во встроенном плеере может отличаться из-за правил сторонних cookies Safari.

`GOOGLE_CLIENT_ID` — публичный идентификатор приложения, не секрет. Не используйте здесь Client Secret или access token. API key для самого OAuth-входа не нужен. Поиск после входа использует OAuth; для поиска без входа можно отдельно ввести ограниченный ключ в настройках сайта. Локально заданный непустой Client ID имеет приоритет над опубликованным; очистка поля возвращает опубликованное значение. Режим `npm start` использует ввод настроек в браузере; переменная применяется к `npm run build`.

Пока Client ID не создан и переменная репозитория не заполнена, публикация кода не активирует реальную авторизацию.

Код IFrame Player API, Data API и входа Google реализован. Проверки выполнены с контролируемыми ответами; живой проект Google и домен ещё не подключены. Чтобы включить интеграцию со своим проектом, выполните настройки ниже и введите публичные параметры в приложении.

1. Выбрать постоянный HTTPS-адрес сайта. Он нужен для ограничений ключа, разрешённых JavaScript origins OAuth и проверки на iPhone. Домены Google для API не заменяют домен самого сайта.
2. В [Google Cloud Console](https://console.cloud.google.com/) создать или выбрать проект и включить **YouTube Data API v3** в APIs & Services → Library.
3. Создать **API key** для публичных данных: поиск, названия, обложки, каналы и публичные комментарии. Для браузерной интеграции ограничить ключ по HTTP referrers, например `https://your-domain.example/*`, и по API — только YouTube Data API v3. Не использовать неограниченный ключ. Браузерный ключ виден посетителю по определению; безопасность обеспечивают ограничения и квоты. Для серверного варианта нужны другие ограничения и закрытое серверное хранение.
4. В **Google Auth Platform** настроить Branding, Audience и Data Access: название, контакт владельца, разрешённые домены, страницу конфиденциальности. Если приложение находится в режиме Testing, добавить тестовые аккаунты. Для публичного использования может потребоваться проверка приложения и запрашиваемых разрешений Google.
5. Создать **OAuth 2.0 Client ID**, тип **Web application**. В Authorized JavaScript origins добавить точный origin сайта, например `https://your-domain.example` (без пути). Для локальной разработки можно отдельно добавить `http://localhost:3000`. Публичный Client ID используется Google Identity Services.
6. При реализации браузерного token flow через Google Identity Services клиентский секрет не нужен. Если будет выбран серверный authorization-code flow для длительных сессий, отдельно настроить точный redirect URI обработчика и хранить Client Secret и refresh tokens только на сервере. Такой обработчик сейчас не реализован; произвольный URI заранее не регистрировать.

7. Откройте сайт → **«Подключить Google / API»** (или значок **«Я»**). Введите ограниченный **YouTube API key** и **OAuth Client ID**, нажмите **«Сохранить настройки»**. Можно настроить только ключ для публичного поиска или Client ID для входа и API-запросов с OAuth.
8. Нажмите **«Войти через Google»** для чтения личных данных. Для оценок, подписок, плейлистов и комментариев отдельно нажмите **«Разрешить изменения»**. Согласие Google само по себе не изменяет аккаунт: запрос записи выполняется по нажатию конкретной кнопки действия.
9. Проверьте поиск, подписки, плейлисты и выбранное видео на реальном iPhone. OAuth-токен живёт только в памяти вкладки; перезагрузка и истечение сессии требуют нового входа. Кнопка **«Отключить Google»** очищает сессию и запрашивает отзыв доступа у Google; при сетевой ошибке отозвать доступ можно в настройках аккаунта.

Не вставлять OAuth Client Secret, access/refresh tokens или неограниченные API-ключи в HTML, Git и чат. Поля приложения предназначены только для ограниченного публичного API key и Client ID и сохраняют их в localStorage браузера. Значения не включаются в Git или сборку. При смене настроек выполняется локальный выход.

## API и разрешения по функциям

| Функции | Официальный интерфейс | Доступ |
| --- | --- | --- |
| Поиск видео | Data API `search.list` | API key для публичного поиска; расходует квоту |
| Названия, длительность, статистика и каналы | `videos.list`, `channels.list` | API key для публичных данных |
| Вход и согласие пользователя | Google Identity Services OAuth 2.0 | OAuth Client ID; согласие каждого пользователя |
| Свои подписки и плейлисты | `subscriptions.list`, `playlists.list`, `playlistItems.list` | OAuth, обычно `youtube.readonly` для чтения |
| Создание/редактирование плейлистов и подписок | Методы записи соответствующих ресурсов | OAuth; отдельное согласие на запись, подходящий scope по документации метода |
| Оценки видео и публикация комментариев | `videos.rate`, `commentThreads.insert`, `comments.insert` | OAuth; обычно `youtube.force-ssl`, проверять требования каждого метода |
| Чтение публичных комментариев | `commentThreads.list`, `comments.list` | API key; если комментарии доступны |
| Воспроизведение, события, очередь, перемотка | YouTube IFrame Player API | Ключ не нужен; действуют ограничения плеера и автора |

Полные имена основных scopes:

- `https://www.googleapis.com/auth/youtube.readonly`
- `https://www.googleapis.com/auth/youtube.force-ssl`

Запрашивать разрешения постепенно, только под выбранные действия. Наличие API key не даёт доступ к аккаунту; Client ID не является согласием пользователя. Вход Google на youtube.com не авторизует автоматически этот сайт. Для личных функций каждый пользователь должен выполнить OAuth-вход хотя бы при первом подключении, а иногда повторно.

## Что не появится от добавления ключей

- Точная персонализированная главная лента YouTube: публичного API для её полного воспроизведения нет. Подборку из подписок можно реализовать отдельно, но она не идентична рекомендациям YouTube.
- Полная история просмотров и Watch Later аккаунта: публичный Data API не предоставляет эквивалент интерфейса приложения. Локальную историю нельзя называть синхронизацией с YouTube.
- Отключение рекламы, выдача Premium, скачивание видеопотока: таких переключателей в официальных публичных API нет.
- Гарантированная фоновая работа и PiP на всех версиях iOS: контролируются браузером и плеером; должны проверяться на реальном устройстве. Desktop mode YouTube не даёт отдельному сайту доступ к внутренностям iframe.
- Автоматические спонсорские таймкоды: YouTube не предоставляет такую базу. Возможный дополнительный сервис — [SponsorBlock](https://wiki.sponsor.ajay.app/w/API_Docs), сторонний и не принадлежащий Google. Его использование меняет исходное условие «только официальные сервисы»; сейчас он не подключён. Его сегменты — пользовательская разметка, без гарантии покрытия и точности.

## Текущие результаты

- Реализованы локальная видеотека, адаптивный интерфейс, официальный IFrame API, очередь, настройки Google, OAuth, поиск с пагинацией, подписки, видео каналов, чтение плейлистов, создание приватного плейлиста, добавление текущего видео, оценки, чтение/публикация комментариев и подписка/отписка.
- Разрешение `youtube.readonly` запрашивается для чтения; `youtube.force-ssl` — отдельно по кнопке разрешения изменений. Ошибки квоты и 401 обрабатываются; OAuth-токены не попадают в localStorage. Создание плейлиста по умолчанию приватное.
- Ответы на комментарии, редактирование/удаление комментариев и существующих плейлистов ещё не реализованы. Полная эквивалентность приложению не достигнута.
- Chromium-проверки используют подменённые Google Identity Services и YouTube API. Живой запрос из текущей облачной среды к `https://www.youtube.com/iframe_api` получил отказ CONNECT-прокси 403. Это не проверка доступности YouTube на устройстве пользователя.
- Подключение реального Google Cloud проекта, публикация сайта, OAuth-проверка Google и тесты на реальном iPhone не выполнены.
