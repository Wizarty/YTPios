# Invidious: интерфейс и подключение

YTP теперь имеет отдельный адаптер Invidious. Это собственный интерфейс в стиле YouTube, не официальный клиент и не точная копия всех экранов YouTube. Piped был рассмотрен как ориентир; его API имеет другую схему и сейчас не подключён.

## Реализовано

- Лента `/api/v1/trending`, категории music/gaming/movies, поиск `/api/v1/search` с пагинацией.
- Карточки видео, канал, длительность и статистика; история и сохранённые видео остаются локальными.
- `/api/v1/videos/:id?local=true`, описание и связанные видео.
- Собственный HTML5-плеер: MP4 с объединёнными аудио и видео из `formatStreams`, выбор качества, Media Session, запрос системного PiP, мини-плеер внутри сайта, очередь.
- HLS, если сервер вернул `hlsUrl`, а браузер поддерживает этот формат нативно. Раздельные DASH-потоки пока не объединяются; доступное качество ограничено совместимыми потоками сервера.
- Свертываемое боковое меню на компьютере, поиск в шапке, нижняя навигация на телефоне, manifest для установки основного приложения на главный экран.

## Как подключить

Нужен работающий экземпляр Invidious с доступным API, видеопрокси, HTTPS и CORS для `https://wizarty.github.io`. **invidious.io — сайт проекта, а не адрес API. piped.video также нельзя подставить как API Invidious.** Не выбирайте произвольный публичный экземпляр без проверки доступности API и условий его оператора.

Адрес вашего сервера задаётся:

1. В интерфейсе через шестерёнку → «Сервер видео» → полный HTTPS-адрес. Настройка сохраняется в браузере. Можно указывать корень сервера или адрес, заканчивающийся на `/api/v1/`.
2. Для всех посетителей — через repository variable **INVIDIOUS_URL** и повторную публикацию Pages через Actions. Значение публичное, без логина, пароля и ключей. Локальная настройка имеет приоритет. Пустое сохранённое локальное значение явно отключает сервер.

Без сервера доступны локальная видеотека и прежний официальный YouTube-плеер с его ограничениями и рекламой. При подключённом сервере ошибка потока показывается пользователю: скрытого переключения на официальный плеер нет.

Размещение самого Invidious на GitHub Pages невозможно. Для него нужны сервер/контейнеры и сопутствующие компоненты по актуальной [инструкции Invidious](https://docs.invidious.io/installation/). Сервер пока не развёрнут. Предварительно выбранная архитектура размещения: GitHub Pages для клиента + VPS с HTTPS для Invidious. Требования к ресурсам и текущие компоненты уточнять по upstream перед покупкой VPS; доступность видеопотоков с IP провайдера не гарантируется.

## Разделение доступа

Google OAuth используется отдельно для официальных подписок, плейлистов, комментариев и оценок. Запросы Invidious выполняются без Authorization, без cookies и без API key. Чтение публичной ленты и воспроизведение через Invidious не требуют Google OAuth.

Подписки Invidious не синхронизируются с Google; это разные системы аккаунтов. Данная версия не создаёт аккаунт Invidious. Персональные рекомендации YouTube не воспроизводятся: главная показывает trending, а похожие видео приходят из ответа выбранного сервера. Обложки пока загружаются напрямую с i.ytimg.com; полной анонимизации трафика нет.

Видеопотоки принимаются только с origin выбранного сервера либо HTTPS-поддоменов googlevideo.com. Script/data URL и URL со встроенными credentials отклоняются. Настройки CSP разрешают HTTPS-соединения и медиа для настраиваемого сервера, но не произвольное выполнение скриптов.

## Проверки и ограничения

`npm run test:invidious` проверяет ленту, поиск, пагинацию, параметры API, реальное воспроизведение локального MP4 через адаптер, выбор качества, похожие видео, повторы после ошибки, сохранение настроек и отсутствие передачи Google Authorization. В тестах API и изображения подменены; обложки на снимках тестовые. Это не проверка рабочего сервера Invidious или доступности видео YouTube.

Системный PiP и фоновое воспроизведение установленного PWA нужно подтвердить на реальном iPhone. Не считать Media Session разрешением работать в фоне. Успешная загрузка контентного потока не является гарантией удаления всей рекламы; SponsorBlock не подключён.

Схема адаптера сверена с [официальной документацией API](https://github.com/iv-org/documentation/blob/master/docs/api.md), прочитанной при реализации.
